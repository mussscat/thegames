# Карточный рогалик — обзор проекта

Документ для быстрого погружения: концепция, игровые механики, стек, устройство кода, процесс. Актуален на 2026-10-10.

## 1. Концепция

Мобильная PWA-игра: **рогалик на основе карточной игры «Дурак»** с механиками в духе **Balatro**. Игрок проходит забег из боёв против соперников; между боями — магазин, где он усиливает свою «сборку» (джокеры, усиления карт, расходники). Цель — сделать каждую раздачу задачкой: что подкинуть, когда отбиться, как расставить джокеров.

- Платформа: веб, PWA, в первую очередь телефон (портрет), плюс широкий экран (раскладка как у Balatro).
- Язык интерфейса: русский. Код, комментарии и коммиты — английский.
- Визуальный стиль: пиксель-арт, тёмный фон с WebGL-«вихрем», яркие карты; шрифты Nunito (текст) и Press Start 2P (заголовки).
- Владелец проекта — Swift/ObjC-разработчик; весь код пишет ИИ-ассистент по согласованным спекам и планам.

## 2. Игровые механики

### 2.1 Бой

- Обычный «Дурак» на 36 карт (6–Т), козырь — масть карты под колодой, подкидывание по рангам на столе, добор до размера руки.
- **Урон наносится только при «Беру»:** взявший получает удар. «Бито» само по себе урона не наносит.
- **Удар = Фишки × Множитель** (как в Balatro), округление вниз:
  1. множитель уровня соперника (обычный ×1, сильный ×1.25, босс ×1.5);
  2. каждая карта, которую берёт защитник: фишки по рангу (6–10 → 1, В–К → 2, Т → 3), затем её усиление, затем «картовые» джокеры атакующего;
  3. заряды фокусов игрока (фишки и множитель);
  4. джокеры атакующего на весь удар, слева направо;
  5. заряд «×» фокуса;
  6. защитные джокеры взявшего;
  7. Щит (фокус).
- Каждый шаг пишется в журнал; на экране — **анимация подсчёта**: табло «Фишки × Множитель», всплывашки над картами и джокерами, итог влетает в полоску HP. Скорость анимации — настройка x1/x1.5/x2/x3, тап — пропуск.
- HP игрока 40, восстанавливается перед каждым боем. Бой — несколько раздач, пока у кого-то не кончится HP.

### 2.2 Забег

- 2 круга по 3 боя: обычный → сильный → босс. HP соперников: круг 1 — 15/20/25, круг 2 — 50/80/120.
- Боссы с правилами: Ведьма (дамы — козыри), Генерал, Фокусник (козырь меняется). На круг — свой босс.
- У сильных соперников 1 джокер, у боссов 2.
- Награда за бой: база + бонус за долю оставшегося HP + проценты от монет + бонусы джокеров/карт.

### 2.3 Джокеры

18 джокеров, до 5 в слотах, **порядок слева направо важен**. Редкость: обычный / редкий / легендарный. Примеры:
- «Червонец/Бубнарь/Трефовик/Пиковик» — +3 фишки за каждую карту своей масти в картах, которые берёт соперник;
- «Злорадство» — +2 множ., если соперник берёт 3+ карты;
- «Козырной туз» — ×2, если среди карт, которые берёт соперник, есть козырь;
- «Копилка ярости» — копит заряд за твои «Бито»;
- «Серийный», «Чистюля», «Коллекционер» — растут по ходу боя/забега;
- «Ростовщик» — ×1.5 тебе и по тебе; «Толстая кожа» — удары по тебе ×0.5, твои ×0.8;
- «Зеркало» — копирует джокера справа;
- правила/экономика: «Длинные руки» (рука 7), «Шулер» (видна верхняя карта колоды), «Мародёр», «Копилка».

### 2.4 Усиления карт (профиль колоды)

Колода общая для двоих, поэтому у каждой стороны — свой «профиль»: какое усиление на какой карте. Усиления: **Золотая** (+3 фишки, когда её забрали), **Острая** (+1 множ.; бьёт любую масть старшим рангом), **Тяжёлая** (к её рангу нельзя подкинуть), **Козырная** (всегда козырь), **Монетная** (+1 монета за отбой ею).

### 2.5 Магазин (в духе Balatro)

- **Витрина:** 2 поштучных слота — джокер / таро / фокус / усиленная карта (веса 60/15/15/10). Рерол меняет только их (2 монеты, +1 за каждый).
- **Паки:** 2 запечатанных пака на визит — «Джокеры», «Таро», «Фокусы», «Колода»; размеры обычный (3, взять 1), большой (5, взять 1), мега (5, взять 2). Вскрытие — анимация с переворотом карт и ореолом редкости.
- **Таро** (8 шт., применяются сразу к картам из «руки» в 5 случайных карт колоды): Солнце/Башня/Звезда/Колесница/Император дают усиления, Смерть копирует усиление, Отшельник удваивает монеты, Колесо Фортуны — шанс джокера.
- Замена усиления на карте — с подтверждением «Острая → Золотая».
- Покупка: тап выделяет товар → «Купить»; описание — наведением или долгим нажатием; нехватка монет — кнопка неактивна.

### 2.6 Фокусы (расходники в бою)

2 слота, переносятся между боями, разыгрываются **только в свой ход, бесплатно**. 10 штук: Подглядывание (рука соперника открыта), Прорицание (3 верхние карты колоды), Пересдача (сбросить 1–2 и добрать), Разгон (+3 множ. к следующему удару), Набивка (+8 фишек), Щит (следующий удар по тебе ×0.5), Копилочка (+4 монеты), Подмена (карта из руки ↔ карта под колодой), Удвоитель (×2 к следующему удару), Смена масти (новый козырь до конца раздачи). Заряды видны значками и как шаги на табло подсчёта.

### 2.7 Баланс

Подбирается **симуляцией**: бот играет сотни забегов (`npm run simulate`). Цель: простой бот проходит круг 1 в 35–45% забегов (живой игрок сильнее). Текущее: ~37%, весь забег ~4%.

## 3. Стек

| Слой | Технологии |
|---|---|
| Язык | TypeScript (strict), ESM |
| Монорепо | npm workspaces: `packages/core`, `packages/durak`, `apps/web` |
| UI | React 19, Vite 8 |
| Анимации | Motion (`motion/react`): layoutId-переходы, `useAnimate`; Web Animations API для «подпрыгиваний» |
| Графика | пиксельные спрайты карт и эмблем рисуются на canvas и кэшируются как data URL; фон — WebGL-шейдер; CSS-переменные для палитр |
| Звук | синтез через WebAudio (тоны, шум), без аудиофайлов |
| Валидация | zod 4 — сохранения забега (версия схемы 9) и настройки в `localStorage`, поле за полем с откатом к умолчаниям |
| PWA | service worker через Workbox (`vite-plugin-pwa`), офлайн, прекэш шрифтов |
| Unit-тесты | Vitest (node-окружение, без DOM) + fast-check (property-тесты) — ~440 тестов |
| E2E | Playwright, профиль Pixel 7 (+ широкие вьюпорты) — ~38 тестов |
| Поиск по коду | ast-index |
| Репозиторий | GitHub `mussscat/thegames` |

Внешних UI-библиотек нет: компоненты, кнопки, подсказки, шторки — свои.

## 4. Устройство кода

```
packages/core/        карты, колода, rng с seed (детерминизм), Result<T, E>
packages/durak/src/
  rules.ts, reducer.ts, deal.ts, types.ts   правила «Дурака» и раздача
  fight.ts             бой: HP, удары, джокеры, заряды фокусов, видимость
  ai.ts                ИИ соперника (стили игры)
  jokers/              каталог, подсчёт удара (scoreTake → шаги журнала), состояние джокеров
  enhancements.ts      усиления и профили колоды
  shop/                таро, паки, взвешенный случайный выбор
  focus/               каталог фокусов, applyFocus
  run/                 забег (run.ts), магазин (shop.ts), экономика
  content/             соперники, боссы
  sim/                 бот и симуляция баланса
apps/web/src/
  games/durak/         экраны боя и магазина, подсчёт и его анимация, сохранение (runSchema, runStorage)
  games/durak/shop/    витрина, паки, вскрытие, таро, фокусы в магазине
  ui/                  пиксельные карты, кнопки, звук, настройки, фон
  components/          HP-полоска, подсказки (CardTip), карты
  lab/                 «лаборатория» (?lab) — стенд для визуала: карты, шрифты, подсветка, паки
e2e/                   Playwright-тесты
docs/superpowers/      спеки (specs/) и планы реализации (plans/)
```

Ключевые принципы:
- **Движок — чистые функции без UI** и без мутаций: `(state, action) → Result<state, error>`. Вся случайность — через rng с seed, хранимый в состоянии (детерминизм, воспроизводимость, симуляция).
- Ошибки — значения (`err('notEnoughCoins')`), в UI мапятся на русские сообщения.
- Сохранение — весь `RunState` в `localStorage`, проверка zod при загрузке; при смене формата растёт `SAVE_VERSION`, старые сейвы считаются повреждёнными (прототип).
- Неизменяемость, маленькие файлы (< 400 строк), явные типы публичных API.

## 5. Процесс разработки

- Каждая фича: **обсуждение → спека** (`docs/superpowers/specs/*-design.md`, на русском) → одобрение → **план** (`docs/superpowers/plans/*.md`: задачи с кодом, тестами, ожидаемым выводом) → одобрение → выполнение по TDD (сначала падающий тест) → финальное ревью всей ветки отдельной сильной моделью → исправления → слияние в main по согласию владельца.
- Фичи ведутся в ветках `feat/*`, в main — перемоткой (fast-forward) после зелёных unit + e2e.
- Коммиты — conventional commits на английском.
- Владелец проверяет интерфейс по скриншотам и даёт правки; интерфейс сверяется с Balatro.

## 6. Состояние и планы
