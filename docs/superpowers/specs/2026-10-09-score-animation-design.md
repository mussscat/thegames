# Анимация подсчёта удара в духе Balatro — дизайн

Дата: 2026-10-09
Статус: реализован (план 3b1)
Основа: спецификация джокеров (§5 «Табло подсчёта», план 3b) и обсуждение с владельцем проекта.

## 1. Цель

Каждый «Беру» — маленькое шоу, как розыгрыш руки в Balatro: видно, какая карта и какой джокер сколько дали, табло растёт на глазах, итог влетает в полоску HP. Игрок понимает, откуда урон, и чувствует свои синергии.

## 2. Когда

На каждый «Беру» — и когда берёт соперник (считают джокеры игрока), и когда берёт игрок (считают джокеры соперника, затем защитные джокеры игрока).

## 3. Последовательность

Источник — журнал шагов удара (`lastScore.steps`, уже есть в движке).

0. **Стоп-кадр.** Взятые карты остаются на столе, пока идёт подсчёт. Над столом — табло: синее поле «Фишки» = 0, красное поле «Множитель» = 1. Шаг уровня соперника (если он не ×1) всплывает над баннером соперника: «×1.25».
1. **Карты по очереди** (в порядке подкидывания): карта подпрыгивает, над ней всплывает синее «+N»; фишки на табло растут. Затем шаг усиления этой карты (золотое «+3» — Золотая, красное «+1 множ.» — Острая) над той же картой. Затем «картовые» джокеры атакующего: билет джокера подпрыгивает, над картой всплывает его вклад.
2. **Джокеры атакующего** слева направо: билет подпрыгивает, над ним всплывает вклад — «+N» (синее, фишки), «+N множ.» (красное), «×N» (крупнее, отдельный звук). Зеркало показывает вклад скопированного джокера. Несработавшие джокеры не двигаются.
3. **Защитные джокеры взявшего** — так же, над их билетами (у соперника — над его джокерами в баннере).
4. **Итог.** Табло вспыхивает «Ф × М = Урон», число летит в полоску HP взявшего, полоска убывает и трясётся; затем взятые карты уезжают в руку взявшего, и игра продолжается.

Звук: каждый шаг — короткий тон, высота растёт от шага к шагу; «×» — отдельный звук; итог — удар.

## 4. Время и управление

- Длительность шага на скорости x1 — 350 мс; итог — 600 мс; табло появляется и исчезает за 200 мс.
- **Настройка «Скорость анимации»: x1 / x1.5 / x2 / x3** (делит все длительности), по умолчанию x1, сохраняется в настройках.
- **Тап/клик по экрану во время подсчёта** — сразу к итогу (пропуск).
- Пока идёт подсчёт, ходы игрока заблокированы и соперник ждёт.
- При `prefers-reduced-motion` — без подпрыгиваний, только смена чисел.

## 5. Архитектура

- **Чистая функция** `scoreTimeline(steps, speed) → TimelineEvent[]`: для каждого шага — момент начала, цель (`card` по id / `joker` по стороне и слоту / `tier`), подпись, значения табло после шага; плюс финальное событие. Покрыта unit-тестами (порядок, тайминги по скорости, подписи, зеркало, пустой журнал).
- **Хук проигрывания** в экране забега: когда действие дало новый подсчитанный удар, экран продолжает показывать состояние до удара (карты на столе), проигрывает события по таймерам, затем показывает новое состояние. Пропуск — сразу финал. ИИ соперника не ходит, пока идёт проигрывание.
- **Компоненты:** табло над столом; всплывашки, привязанные к положению цели на экране (карты и билеты помечены атрибутами `data-score-card` / `data-score-joker`), рендер поверх всего; подпрыгивание цели — класс на элементе на время шага.
- Нынешняя подпись урона у полоски HP заменяется финалом табло.
- Настройка скорости — в `settings` (валидация zod, по умолчанию x1).

## 6. Тестирование

- Unit: `scoreTimeline` (порядок шагов, моменты на x1 и x3, финал, подписи «+3», «+1 множ.», «×2», зеркало, удар без шагов), настройка скорости (валидация, по умолчанию).
- E2E: на «Беру» появляется табло и всплывашки над картами; тап пропускает к итогу; HP меняется после итога; скорость x3 сохраняется после перезагрузки.

## 7. Вне рамок

Перетаскивание джокеров (остаётся в плане 3b отдельной задачей), новые миниатюры джокеров, музыка.
